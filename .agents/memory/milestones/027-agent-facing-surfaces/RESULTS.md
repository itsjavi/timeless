### Why the CEM gap is the load-bearing number

21 of 57 contracts appear in `custom-elements.json`, so every CEM-consuming tool sees 37% of the
library. There is no manifest concept for a class root configured by `data-ui-*`, which means the 36
CSS contracts — the majority, and the centre of the project's stated philosophy — are invisible to
`cem mcp`, `cem lsp`, and `vscode-web-components-ai`. This is what forces every artifact in the plan
to generate from `componentContracts` instead of from the manifest, and what makes the phase 3 spike
a measurement rather than an adoption.

## Open decisions

**Whether the markup checker becomes public API.** `validate_markup` is the one MCP capability no
competing library can offer, and the same function powers the phase 5 eval. Exporting it from
`@timelessui/components` makes it reusable by consumers writing their own lint rules, and makes it a
public surface that must then be versioned and kept stable. Keeping it internal — a script, or a
module in a future MCP package — keeps the public surface small, which milestone 021 spent effort
achieving, but means the MCP server cannot depend on the published package and must live in this
repository. Deferred to the milestone that builds the server. Phase 5 writes it as a plain
unit-tested function with no export from the barrel, which leaves both routes open.

**Whether `llms-full.txt` ships at all.** Decided on the measured build-time delta in phase 1.4. The
argument for shipping is that it costs a concatenation of files phase 1.1 already emits. The
argument against is that Astro deleted its own `llms.txt` partly over a 44-second CI cost, and Nuxt
UI ships its 1M-token equivalent with a warning attached. If it is dropped, that is recorded here
rather than silently omitted.

**Whether `starlight-dot-md` is adopted or replaced by twenty lines.** A dependency that tracks
Starlight's route internals against a hand-written endpoint over `getCollection('docs')`. The plugin
wins if it handles Starlight 0.41 and Astro 7 cleanly; the endpoint wins if it does not, and also
gives explicit control over frontmatter and import stripping. Resolved in phase 1.2 by testing, and
the outcome recorded here.
